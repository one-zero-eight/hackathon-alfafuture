# Методы отбора новостей под профиль

Раздел: news_search
Дата: 2026-10-22 (исследование), перенесено 2026-10-24 · Источник: материалы пилота и второго прогона (папка `exp/` до рефакторинга, коммиты 38e5f8b и e43c8df в истории git)

## Что измеряем
Как из недельного потока (около 2 000 сюжетов) выбрать новости, которые влияют на решения пользователя, описанного только параметрами входа (роль, ОКВЭД, регион, размер, продукты). Гипотеза: развёрнутый профиль плюс диверсификация лучше, чем отбор по графу тегов или по сырым параметрам.

## Метрика
- **nDCG@10** (0–1, больше лучше): качество ранжирования по разметке релевантности (два прогона разметки, согласие по линейному κ = 0,73).
- **Итоговая оценка записки /10** (больше лучше): слепое сравнение записок вслепую судьёй по эталону «полностью информированный аналитик».
- **Доля неподтверждённых утверждений** (меньше лучше).

## Данные и окружение
Одна неделя новостей, 2 008 сюжетов после дедупликации, 16 синтетических профилей только из параметров (и 6 свободных персон в пилоте). Читатель — Haiku, судья и разметка — Sonnet: это модели-заменители, не из списка организаторов. Абсолютные оценки с одобренными моделями будут другими.

## Сравниваемые методы
| Метод | Суть |
|---|---|
| xQuAD | вопросы-потребности + плотный поиск + диверсификация по аспектам; в коде — `dense_xquad` |
| base | то же без диверсификации |
| G1 | отбор только по графу отраслей (BFS по тегам) |
| X1 | гибрид «граф → эмбеддинги» |
| 5+5 | 5 лучших по эмбеддингам + 5 лучших по графу |
| E3 | переранжирование кросс-энкодером |
| P14 | метод пилота на шаблонных запросах |

## Результаты
Конец-в-конец (раунд 3, 3 прогона судьи):

| Метод | Оценка /10 | Покрытие ключевых пунктов | Точность решений | Неподтверждённые утверждения |
|---|---|---|---|---|
| xQuAD | **6,17 ± 0,37** | **0,40** | **0,86** | **1,3 %** |
| 5+5 | 5,68 ± 0,32 | 0,38 | 0,80 | 2,9 % |
| base | 5,53 ± 0,27 | 0,37 | 0,78 | 4,5 % |
| E3 | 5,22 ± 0,36 | 0,35 | 0,84 | 1,9 % |
| P14 | 4,29 ± 0,37 | 0,30 | 0,62 | 3,6 % |
| X1 | 4,12 ± 0,40 | 0,27 | 0,62 | 4,4 % |
| G1 | 3,68 ± 0,27 | 0,23 | 0,64 | 6,1 % |

Представление профиля (nDCG@10, тест): сырые метки 0,12 → вопросы-потребности 0,51 → потребности + шаблоны ролей 0,53.
Кодировщики (nDCG@10, тест): e5-large-instruct 0,60, Qwen3-Emb-0.6B 0,56, bge-m3 0,53, USER-bge-m3 0,50, FRIDA 0,48. В пилоте на других запросах: bge-m3 0,73 > e5-large 0,67 > e5-small 0,61.
Ширина входа: карточки 4,91, карточки + связанные 4,25, карточки + 40 заголовков 6,08.

## Вывод
Решает представление профиля; граф как ранжировщик проигрывает (18 разделов ОКВЭД дают много равных оценок); разнообразие важнее точности; кросс-энкодер не помогает. В коде методом по умолчанию стал `dense_xquad` (bge-m3, потребности + HyDE, xQuAD). Поиск по основам слов как второй источник поднял полноту с 0,59 до 0,63 на золотом наборе из 122 тыс. новостей; один лексический фильтр пропускал больше половины релевантного.

## Ограничения
Одна неделя, 16 профилей; модели-заменители одного семейства; метод `dense_xquad` в виде, как он собран в `news_search`, этими экспериментами целиком не измерялся (в эксперименте не было слоя событийных карточек); `e5-large-instruct` в раунде 3 не проверялся. Кодировщик e5 в коде оставлен только для `dense_llm`.

## Как воспроизвести
Исходные скрипты и данные исследования остались в истории git (путь `exp/v2/` до коммита рефакторинга). Новый замер на живом корпусе: `curl -X POST localhost:8002/search -d '{"company":…,"line":…,"method":"lexical|dense_llm|dense_xquad"}'` и сравнение выдач; метрики качества для него ещё не размечены.
