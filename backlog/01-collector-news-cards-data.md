# Сборщик: данные для карточек новостей

Раздел: `collector`.

Актуальный отбор новостей должен опираться на эмбеддинги «карточки» новости. Нужно, чтобы в Postgres было достаточно данных для карточки.

## Результат проверки БД (2026-10-24, только чтение)

Данных недостаточно:
- статей 336 381, со своим текстом 20 162 (6 %), остальные 94 % — только заголовок и ссылка (в основном из Google News);
- средняя длина текста `rss_description` — около 181 знака; текст от 500 знаков есть у 157 статей;
- `published_at`: 714 пустых, есть `1970-01-01` и дата в будущем (2026-12-01);
- теги не проставлены ни у одной статьи (таблицы тегирования пусты).

Не проверялось: качество текста (HTML, мусор), доля дублей.

## Задача

1. Убрать Google News из источников: удалить периодический проход `DEEP_EVERY`, запросы `site:` и по темам, источники `gn:<издание>`, режимы `-backfill gn` и `-backfill gnsite`, файл `topics.txt` и упоминания в `docs/collector.md`, README и `.env.example`. Что делать с уже собранными заметками из Google News (около 316 тыс. статей без текста), решает пользователь; без его решения ничего не удалять.
2. Читать полный текст статьи со страницы издания там, где из ленты приходит только анонс.
3. Чистить `published_at`: не принимать 1970 и будущие даты.
4. Хранить в БД происхождение текста и статус докачки; миграция без потери существующих статей.
5. Определить вместе с пользователем, что входит в карточку новости, и описать это в `docs/`.
6. Замерить до и после: долю статей с текстом от 500 знаков, число статей в сутки по изданиям.

## Готово, когда

Для статей последних 30 дней доля с текстом от 500 знаков измерена, цель согласована с пользователем; `docker/check.sh` зелёный.
