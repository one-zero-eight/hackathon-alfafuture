# Метрики персонализации: A/B по параметрам компании

Разделы: `news_search`, `backend`.

Провести A/B-тестирование по каждому параметру из `external-docs/company/`, проанализировать отзывчивость и составить план дальнейших действий.

## Параметры

Из `df_Uid_data_hack.csv`: ORG_TYPE, OKFS_NAME, COMPANY_AGE_YEARS_GRADATION, ECO_MARK_LABEL, MAINOKVED_CODE/NAME, NEGATIVEMARK, AMOUNT_WORKERS_FNS/SPARK_GRADATION, CL_TYPE, флаги продуктов (RKO, GAR, LOA, LEA, DEP, ZPP), FTS_FLAG, FTS_COUNTRY_NAME, FACTORING_MARK, REVENUE_COMPANY, GROUP_ID, CITY, REGION. Из связанных файлов: город и РЦ филиала, платёжные связи.

## Задача

1. Выбрать 30–50 компаний, стратифицированно по ОКВЭД, региону, размеру.
2. Для каждой построить профиль полный и профиль без одного параметра (или с подменой значения); поиск на одном и том же срезе корпуса. «A/B» здесь — офлайн-сравнение выдач, живых пользователей нет. Если нужен другой смысл, сказать.
3. Метрики: пересечение топ-K полной и урезанной выдачи, корреляция порядка, релевантность по судье-LLM, разнообразие выдачи, токены на профиль.
4. Таблица «параметр → эффект»: что меняет выдачу и повышает релевантность, что шум, что можно убрать.
5. План действий: какие параметры усилить, какие убрать. Отчёт `news_search/benchmarks/personalization-ab.md`.

Метод поиска берётся из конфига бэкенда. Лучше запускать после задачи 01 (иначе поиск идёт по заголовкам). Список компаний общий с задачей 06.
