# Обратная связь: проверка оркестрации и время фикстур

Раздел: backend
Дата: 2026-10-26 · Версия: backend/feedback-orchestration (рабочее дерево)

## Что измеряем

Гипотеза: существующих /refine, /page и /reply достаточно для вопросов, дополнений, смены перспективы, добавления статьи и удаления без переписывания алгоритмов других разделов. Недостающий пересмотр решений/предложений должен завершаться явным отказом и не менять страницу. Дополнительно измеряется время от отправки сообщения до чтения результата на фикстурах.

## Метрика

Фактический конечный статус, количество изменённых виджетов/связей, сохранение происхождения/версий/пользовательского состояния. Задержка HTTP/curl операции в мс (меньше лучше). Успех зависимого сценария — корректный blocked без частичной записи, а не изображение выполненного анализа.

## Данные и окружение

Четыре uvicorn-сервиса backend/agents/news_search/analytics на loopback; PostgreSQL 18.6 в отдельном Docker-контейнере и временной схеме. Docker Desktop Linux: 20 CPU, около 61,2 GiB RAM. Python 3.13, uv workspace. Фикстура из 120 новостей, hash_encoder вместо моделей, шлюз и загружаемая статья заменены фикстурами. Реальные HTTP, клиент Agents и curl; PYTHONHASHSEED=0. По одному прогону сценария.

## Сравниваемые методы

Используется dense_xquad как единственный существующий метод /refine. lexical/dense_llm проверены тестами на явный unsupported_search_method, без молчаливого переключения или сравнительного замера качества.

| Сценарий | Статус | Изменений | Время, мс |
|---|---|---:|---:|
| question | completed | 0 | 375,3 |
| extend | completed | 50 | 1426,5 |

| link | completed | 50 | 1526,3 |

| proposal | blocked | 0 | 230,6 |
| clarify | needs_clarification | 0 | 216,4 |

Изменения включают виджеты и связи, поэтому одна цепочка — несколько элементов. Дополнительно прошли server-side undo и force-refresh: версия увеличилась, прежнее исключение восстановилось вместе со страницей, эффективный регион и ID пользовательской статьи сохранились. Журналы операций без потерь (incomplete=false). Предыдущий HTTP/curl smoke #29 также прошёл после перехода чата на очередь.

Платных вызовов не было. Фикстурный gateway возвращает синтетический usage; эти числа не являются оценкой реальной цены или токенов Gemma. Классификатор и промпт проверяются отдельно: [agents/benchmarks/feedback-intents.md](../../agents/benchmarks/feedback-intents.md).

## Вывод

Оркестрация поддерживаемых сценариев работает через текущие HTTP-контракты; зависимости #28 выявляются до публикации. Асинхронный API не удерживает пользовательский HTTP-запрос на время всей аналитики. Требуются доработки frontend #25 для polling/undo и analytics #28 для оставшихся сценариев. Живые скорость, качество и бюджет не подтверждены.

## Ограничения

Один прогон на сценарий, синтетические новости/ответы и искусственная статья. Время включает запись/чтение журнала и операции, но не ожидание очереди под нагрузкой. Нет вывода о качестве Gemma, настоящего dense-поиска, платных токенах или производительности в промышленном корпусе. Загрузка реального сайта не измерялась: отдельные тесты проверяют DNS/IP/TLS/редиректы/лимиты с искусственным транспортом, а реальный дочерний fetch-процесс — отказ для loopback. Матрицы рисков и пересмотр решений не реализованы в backend вместо #28.
