# Доступность лент и прирост корпуса за проход

Раздел: collector
Дата: 2026-10-24 · Версия кода: рефакторинг на семь разделов (до первого коммита) · Автор: ИИ-агент по заданию

## Что измеряем
Сколько источников из `sources.json` читаются обычным HTTP-клиентом и сколько новых статей даёт один проход.

## Метрика
Доля прочитанных лент (больше лучше), число новых статей за проход, причины отказов.

## Данные и окружение
292 источника с лентой (396 в списке, из них 101 только через Google News и 3 встроенных), клиент Go с браузерным User-Agent, сеть разработчика, `LLM_ENABLED=false`, корпус из дампа (300 886 статей).

## Сравниваемые методы
Только текущий клиент. Для проверки причин отказа несколько лент открыты через curl из контейнера.

## Результаты
| Показатель | Значение |
|---|---|
| Прочитано лент | 133 из 292 |
| Новых статей за первый проход | 924 |
| Отказы: ошибка запроса (TLS) | 79 |
| Отказы: HTTP 403 (в основном bezformata) | 16 |
| Отказы: лента не разбирается | 2 |
| Отказы: HTTP 429 | 1 |
| Google News, скользящий проход (издания) | 1 185 запросов, около 2 400 новых статей за первые 100 |

## Вывод
Отказы TLS воспроизводятся и curl из той же сети, то есть это ограничение сети, а не клиента. Охват лент зависит от сети запуска; на сервере команды результат может отличаться. Глубину обеспечивает Google News.

## Ограничения
Один проход, одна сеть; 403 могут зависеть от времени.

## Как воспроизвести
```bash
docker compose --env-file .env -f docker/compose.yaml up -d collector
docker compose --env-file .env -f docker/compose.yaml logs collector | grep -E "feeds pass finished|feed fetch failed"
```
