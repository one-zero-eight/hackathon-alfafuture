# 1. Сбор информации (Go-сервис `collector`)

Наполняет Postgres новостями и проставляет теги. Код: [collector/](../collector/). Подробный справочник по ядру сервиса (схема БД, тегирование, HTTP API, тесты): [collector-news-service.md](collector-news-service.md), словарь тегов: [collector-tag-vocabulary.md](collector-tag-vocabulary.md).

## Что делает, шаг за шагом

1. При старте читает настройки, создаёт таблицы (словарь тегов, источники, статьи, попытки тегирования, региональные метки) и загружает [sources.json](../collector/sources.json) и [topics.txt](../collector/topics.txt). Сломанный файл источников останавливает сервис.
2. **Три встроенных издания** (РБК, «Коммерсантъ», Банк России) опрашиваются каждые `POLL_INTERVAL` (10 минут). Для РБК берётся полный текст из ленты, для ЦБ текст докачивается со страницы статьи.
3. **Остальные источники** из `sources.json` (около 390 изданий, из них 287 региональных) читаются каждые `FEEDS_EVERY` (15 минут): 12 лент параллельно, текст статьи — описание из ленты (до 2000 знаков).
4. **Глубина через Google News** каждые `DEEP_EVERY` (6 часов): скользящее окно в 3 дня. Для каждого издания запрос `site:<сайт>` по окнам в 1 день и для каждой темы из `topics.txt` по окну в 3 дня (до 100 заметок на запрос). Заметки без своей ленты складываются под источник издания, темы — под источник `gn:<издание>`. У таких заметок есть только заголовок и ссылка (на редирект Google News), текста нет. Если Google отвечает 429/503 и после пяти повторов (пауза 5–25 с), он считает нас ботом: проход сразу останавливается (в логе `Google News blocks requests, pass stopped`, затем `rolling Google News pass failed`), второй вид прохода пропускается, следующая попытка — через `DEEP_EVERY`. Раньше проход продолжал все ~1 200 запросов, при блокировке занимал около 6 часов и всё это время останавливал опрос лент.
5. Каждая статья пишется через общую проверку: уникальный ключ `(источник, ключ статьи)`, поэтому повторные проходы ничего не дублируют. Ключ — хеш адреса.
6. **Теги.** Один воркер берёт статьи с текстом по порядку, отправляет модели текст и фиксированный словарь, но из 365 тегов географии — только кандидатов статьи (см. «Предотбор географии» ниже), проверяет ответ (цитаты должны быть дословными) и сохраняет теги и события. Это единственное обращение к ИИ вне сервиса `agents`: клиент LLM остаётся внутри Go-сервиса. При исчерпании бюджета воркер встаёт на паузу до 03:00 по Москве.
7. **Геотеги региона.** После каждого прохода лент модель Gemma смотрит на заголовки новых статей региональных изданий (по 60 штук) и оставляет региональный тег только тем, что относятся именно к региону издания. Если у издания есть раздел «в регионе» (`region_sections`), статьи этого раздела получают тег сразу, без модели. Решения лежат в `article_geo`; пустой `region_tag` значит «проверено, не региональная».

## Предотбор географии для тегирования

География — около трёх четвертей словаря, поэтому модель видит не все 365 таких тегов, а только кандидатов статьи. Код: `internal/news/tagging/geography.go`.

1. **Поиск в тексте.** Слова статьи и названия/алиасы тегов географии приводятся к основам (стеммер Snowball для русского). Тег — кандидат, если его название встречается подряд идущими основами («в Китае», «Московской области»). Однословные названия, совпадающие со служебными словами («Того»), не ищутся. У коротких основ (до четырёх букв) слово статьи должно ещё и начинаться с названия без последней буквы, иначе «Дания» совпадала бы с «данные», а «Мали» с «малого».
2. **Вопрос модели о местах — для каждой статьи.** Поиск в тексте не узнаёт прилагательные («российские военные»), столицы и косвенные названия, а модель тегирования всё равно называет такую страну, и ответ отклоняется целиком. Поэтому воркер берёт до 30 статей из головы очереди и одним запросом к Gemma (без словаря, около 140 токенов на статью) просит перечислить все страны и регионы России, упомянутые или подразумеваемые в статье: прилагательные, столицы, города и органы власти заменить страной или регионом («российские военные» → Россия, «Киев» → Украина), названия писать полностью и в именительном падеже. Лишнее место не страшно (модель тегирования его просто не возьмёт), пропущенное — хуже. Gemma, а не модель тегирования: рассуждающая модель (deepseek) тратит на этот пакет весь лимит токенов и не успевает ответить. Ответ сопоставляется со словарём тем же поиском; несопоставленные названия отбрасываются. Модель не называет теги. Ответы хранятся в памяти воркера до тегирования этих статей. Кандидаты статьи — объединение шагов 1 и 2.
3. **Запрос тегирования.** В справочник запроса входят все теги кроме географии, оба тега масштаба (`geography:scope:russia`, `geography:scope:international`) всегда и найденные кандидаты. Версия prompt — `news-tags-v2`.
4. **Проверка ответа.** Набор тегов, показанных модели, берётся из сохранённого запроса попытки; тег вне него отклоняется так же, как тег вне словаря.

Ограничения: если ответ шага 2 не разобран после трёх попыток, статьи пакета получают только совпадения шага 1 (предупреждение в логе). Место, которое не нашли ни поиск, ни вопрос модели, модель тегирования назначить не может: такой ответ отклоняется.

## Файл источников `collector/sources.json`

Список объектов:

| Поле | Смысл |
|---|---|
| `id` | уникальный короткий идентификатор источника |
| `name` | название издания |
| `url` | адрес RSS/Atom-ленты; нет ленты — источник читается только через Google News |
| `host` | сайт издания (для запросов `site:`) |
| `region` | тег региональности `geography:region:NNN` из словаря или `null` для федеральных |
| `region_sections` | необязательно: категории ленты, статьи которых считаются региональными без проверки моделью |
| `native` | `true` для РБК, «Коммерсанта», ЦБ: их ленту читает встроенный сборщик, а список используется только для Google News |

Чтобы добавить издание, допишите строку и перезапустите сервис; без пересборки образа — подмонтируйте свой файл поверх `/app/sources.json`.

## Настройки

Все переменные описаны в [collector/.env.example](../collector/.env.example). Главные:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DATABASE_URL` | — | Postgres |
| `LLM_ENABLED` | `true` | `false`: только сбор, без тегов, геотегов и расходов |
| `TAGGING_ENABLED` | `true` | `false`: без тегирования (дорогое, ~17 тыс. токенов на статью); геотеги остаются. Действует только при `LLM_ENABLED=true` |
| `GEOTAG_ENABLED` | `true` | `false`: без геотегов региональных изданий. Действует только при `LLM_ENABLED=true` |
| `LLM_API_KEY`, `LLM_MODEL` | —, Gemma 4 26B | ключ организатора и модель для тегов (в compose — `google/gemma-4-26b-a4b-it`) |
| `SOURCES_FILE`, `TOPICS_FILE` | `sources.json`, `topics.txt` | списки источников и тем |
| `FEEDS_EVERY`, `DEEP_EVERY` | `15m`, `6h` | периоды проходов |

## Заполнение корпуса задним числом

Разовая загрузка глубокой истории (запускать можно повторно: сделанные запросы хранятся в таблице `fetch_windows`, дубли отсекаются):

```bash
docker compose --env-file .env -f docker/compose.yaml run --rm collector news -backfill gnsite -days 60 -step 2   # по изданиям
docker compose --env-file .env -f docker/compose.yaml run --rm collector news -backfill gn -days 60 -step 7       # по темам
docker compose --env-file .env -f docker/compose.yaml run --rm collector news -backfill gnsite -days 60 -step 5 -regional   # только региональные
```

Google News иногда отвечает 429: запросы повторяются с паузой, пустые ответы повторятся при следующем запуске.

## Ограничения

- Заметки из Google News — только заголовок, поэтому теги им не ставятся (воркер берёт статьи с текстом), а ссылка ведёт через редирект Google, не на оригинал.
- **Тегирование дорогое.** Даже после предотбора географии запрос несёт остальные 160 тегов с описаниями (замер на Gemma: 17 267 токенов на вход вместо 57 650, `collector/benchmarks/tagging-cost.md`), а воркер идёт по очереди статей подряд. При `LLM_ENABLED=true` он будет расходовать бюджет, пока провайдер не ответит «бюджет исчерпан» (тогда пауза до 03:00 по Москве). Для сбора без расходов задайте `LLM_ENABLED=false`; чтобы оставить только дешёвые геотеги, задайте `TAGGING_ENABLED=false`.
- Проверено вживую по одному запросу: тегирование статьи Gemma проходит проверку словаря; геотег по четырём заголовкам разделил региональные и федеральные (тесты `TestLiveWorker`, `TestLiveClassify`, запуск с `LIVE_LLM_TEST=1`).
- РБК и часть сайтов недоступны из некоторых сетей (ошибка TLS); в логе `feed fetch failed` или `source poll failed`.
- Google News блокирует частые запросы с одного адреса (HTTP 503, страница «unusual traffic»). Так было с 2026-10-24 после массовой догрузки 20–23.10: Google News не дал ни одной новости. Обходить блокировку (прокси, смена адреса) не нужно; проверить, снята ли она: `curl -s -o /dev/null -w "%{http_code}" "https://news.google.com/rss?hl=ru&gl=RU&ceid=RU:ru"` (200 — снята).
- Пакетный разбор статей из старого дампа корпуса (80 МБ, до рефакторинга без тегов) не переразмечается: у них статус `completed`.
