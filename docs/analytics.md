# 4. Аналитика (Python-сервис `analytics`)

Превращает отобранные новости в страницу: новости → аналитика → решения, с цитатами-доказательствами. Код: [analytics/](../analytics/). Цепочка Льва (ветка `ranking/reasoning-chain`).

## Что делает, шаг за шагом

Для каждой из первых 10 новостей (`limit`) строится своя цепочка:

1. **План** ([chain.py](../analytics/chain.py), `plan`): как событие может дойти до компании (напрямую, через продукты банка, ресурсы, торговлю). Без карточки события это всегда «напрямую».
2. **Аналитика (до 3 шагов).** Агент `analytics_step` пишет одно предложение о сфере: ОКВЭД, регион, численность, отрасли поставщиков и покупателей, введённая сфера. Названия компании, выручки и продуктов банка в этом запросе нет. Материалы для шага: сама новость, связанные новости из пар поиска (только на первом шаге), тезисы Альфа-Банка и другие новости страницы, найденные лексическим поиском по прошлой мысли. Цитата проверяется кодом: она должна быть дословным куском материала, иначе мысль отбрасывается. Цепочки разных новостей (шаги аналитики и решение) идут параллельно в пуле из `ANALYTICS_WORKERS` потоков (по умолчанию 6), порядок новостей на странице сохраняется; шаги одной новости остаются последовательными, потому что каждая мысль даёт запрос для следующего поиска. Пакеты проверки `verify` тоже идут параллельно. Шаг аналитики пишет Gemma 4 26B A4B: самая многочисленная часть вызовов, замер в [benchmarks/parallel-and-models.md](../analytics/benchmarks/parallel-and-models.md).
3. **Позиция банка.** К аналитике добавляется ближайший тезис из PDF Альфа-Банка (поиск bge-m3), только если он имеет с заголовком общий предмет и не про другой год.
4. **Решение.** Агент `decision` видит факты компании (выручка, продукты, платежи) и правила роли. Если сотрудник написал не только должность, а одну-две строки, агент `role_brief` дополняет правила из [data/roles.json](../analytics/data/roles.json); голое название должности модель не вызывает. Решение — одно действие с 2–4 рисками (вероятность и влияние 1–4), типом (риск, возможность, наблюдение) и сроком: `urgent` до месяца, `medium_term` до года, `not_urgent` дольше. Срок с карточки события, если она есть, важнее ответа модели. Уверенность вывода: `reliable`, если цитат из разных источников две и больше; `probable`, если источник один; `possible`, если вторая модель не подтвердила вывод.
5. **Проверка.** После всех цепочек агент `verify` (другая модель) пачками по 4 проверяет, следует ли вывод из цитаты. Вывод без подтверждения остаётся на странице с уверенностью «возможно».
6. **Сборка страницы.** Виджеты `n`, `a`, `d` и стрелки между ними; у новости — ссылка на оригинал, источник и дата; у тезиса банка — ссылка на страницу PDF; у решения — один уточняющий вопрос из первого риска. Лишнее предложение банка, не связанное с заголовком, убирается.
7. **Синтез** ([synthesis.py](../analytics/synthesis.py)). После цепочек по отдельным новостям агент `synthesis` пишет один вывод для сферы (ОКВЭД, регион, введённая сфера), без названия компании, выручки и продуктов банка. В вывод входят минимум две новости одной истории: связанные пары поиска или общие теги, а если таких связей нет — все новости страницы. Цитата проверяется дословно, как в шаге 2. Тезис банка попадает в материалы, если делит предмет с заголовком, и остаётся в выводе только с дословной цитатой. Затем агент `synthesis_decision` пишет одно действие уже для этой компании, по правилам роли и фактам карточки. У вывода есть тип (`risk`, `opportunity`, `observation`) и горизонт (`urgent` до месяца, `medium_term` до года, `not_urgent` дольше). На странице это виджеты `s1` и `sd1` и стрелки от каждой новости истории к `s1`. Цепочки по одной новости этот шаг не заменяет.

Любой сбой одной цепочки оставляет на странице всё, что успело построиться (новость, аналитику).

## Вход и выход

`POST /page`:

```json
{"profile": {"label": "Иркутск", "okved": "F", "okved_code": "41.20", "okved_name": "Строительство", "region": "…",
             "products": ["credit"], "products_ru": ["кредиты"], "facts": "…", "date_label": "…"},
 "role": "CFO", "sphere": "закупки", "news": [/* top из news_search */], "pairs": [[0, 5]], "triz": true, "limit": 10}
```

Все поля `profile` необязательны; `role` — идентификатор правил из `roles.json`. Ответ: `{"version", "company", "widgets", "links", "journal"}` (поля виджетов — в [backend.md](backend.md)). `POST /reply` отвечает на вопрос по виджету только по его тексту и фактам о компании. Один расчёт занимает минуты (десятки вызовов LLM).

## Тезисы Альфа-Банка из PDF

Новый PDF можно положить в локальную папку с PDF Альфа-Банка (в `docker/compose.yaml` она примонтирована в `/papers`) и разобрать без правок кода:

```bash
docker compose --env-file .env -f docker/compose.yaml run --rm analytics python -m analytics.alfa /papers
```

Страницы с текстом читает агент `alfa_page`, страницы-картинки (слайды) рендерятся в JPEG (poppler) и читаются моделью Qwen3-VL. У текстовой страницы тезис остаётся, только если цитата дословно есть на странице. Результат кэшируется по хешу файла и номеру страницы и пишется в `theses.jsonl` (том `analytics_data`). Расход LLM — десятки–сотни вызовов, запускайте осознанно. Без `theses.jsonl` страница строится без позиции банка.

## Настройки и проверка

`AGENTS_URL`, `ANALYTICS_DATA` (папка данных), `PAPERS_DIR`, `HF_HOME`, `ANALYTICS_WORKERS` (сколько новостей разбирается одновременно, по умолчанию 6).

```bash
uv run pytest analytics    # офлайн, агенты подменены
```

## Расход

Замер на одном профиле («Делимобиль», 10 новостей, метод `lexical`): около 80 вызовов LLM, около 13 условных единиц стоимости по `usage.cost` (единица, по-видимому, рубль, это не подтверждено). Основная часть — шаги аналитики и проверка.

## Ограничения

- Агент `analytics_step` предупреждён, что новость уже отобрана поиском как полезная компании и роли: без этого модель отбрасывала общие новости для компании, о которой известно только название. Если для компании есть карточка банка (`company_id`), она тоже попадает в запрос.
- Правила решений есть для четырёх должностей (финансовый директор, генеральный директор, главный бухгалтер, руководитель казначейства). Для любой другой роли и для сфер («Глава найма») запасные правила — финансового директора, а строка сотрудника их дополняет.
- Новости приходят из живого поиска и не имеют карточки события, поэтому тег «отрасль» у новостей не ставится, а план цепочки всегда «напрямую». Срок тогда берётся из ответа модели, а не из константы.
- Одна страница за раз.
- Подбор новостей по сфере, который раньше делали по недельным карточкам исследования, теперь делает `news_search`.
- Поиск ближайшего слова в `backend/focus.py` может принять похожее слово за отрасль («найма» близко к «наука»): влияет только на подпись сферы.
