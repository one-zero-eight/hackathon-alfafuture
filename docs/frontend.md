# 6. Frontend (React + TypeScript + Vite)

Интерфейс: три блока «Новости → Аналитика → Решения», стрелки между виджетами, матрица рисков, чат по виджету и стрелке, стартовое меню выбора компании и роли. Код: [frontend/](../frontend/). Контракт с бэкендом: [backend.md](backend.md).

## Как это работает

0. Красная полоса «Альфа-Бизнес / Новостная аналитика» видна на каждом экране: это вход в сервис из оболочки банка, он не прячется. Без сохранённого профиля показывается стартовое меню: слева прокручиваемый список компаний (`GET /api/companies`, подгрузка при прокрутке, поиск), справа поле роли и кнопка «Сбор новостей». «Посмотреть демо» открывает демо-страницу, «Новая аналитика» в шапке возвращает в меню. На карточках тег `kind`: факт, вывод модели или гипотеза.
1. После выбора фронт запрашивает `GET /api/page` и рисует заголовки виджетов и стрелки (демо-страница, пока нет профиля). Ключ последнего профиля берётся из `localStorage`.
2. Меню отправляет `POST /api/profile` (id компании и роль), затем раз в 1,5 секунды опрашивает `GET /api/profile/{key}` и рисует вертикальный таймлайн из трёх этапов: «Поиск новостей», «Найдено n новостей, выбор актуального», «ИИ анализирует n новостей, данные компании и аналитические статьи от АльфаБанк». Если страница уже в кэше, меню сразу открывает её. При `ready` перезагружает страницу с `?profile={key}`.
3. Содержимое виджета, матрица рисков и описание стрелки подгружаются по клику и кэшируются.
4. Ответ чата может содержать патч страницы; фронт применяет его или перезагружает страницу при конфликте версий.
5. Кнопка «Спросить ИИ» (правый нижний угол) есть на всех экранах: стартовое меню, загрузка, ошибка, доска. Она открывает чат по единственному раскрытому виджету, иначе по первому виджету страницы; без страницы показывает подсказку. Вопрос, правка («Исправить вывод»), вставка ссылки, удаление («Удалить как неактуальное») уходят одним путём: `POST /api/chat`. Ответ с `patch` фронт превращает в карточку в чате: сценарий (`scenario.kind` от сервера, иначе предположение интерфейса по операциям патча), что добавлено, заменено, удалено, и кнопка «Откатить».
6. Откат пока локальный: фронт возвращает прежние заголовки и стрелки, сервер хранит изменённую страницу (нужен эндпоинт отката, см. ниже).

## Проверка эндпоинтов (ишью #25)

Проверено curl против запущенного стека (бэкенд :8100), 2026-10-25.

| Эндпоинт | Результат |
|---|---|
| `GET /health`, `/api/companies`, `/api/page`, `/api/widgets/{id}`, `/api/widgets/{id}/risks`, `/api/links/{id}` | работает |
| `GET /api/profile/{key}`, `POST /api/profile` | работает; повторный запрос тем же профилем отдаёт кэш (`cached`), пересборки нет: нужен новый |
| `POST /api/chat`, вопрос | работает на профиле (ответ analytics `/reply`); на демо-странице заглушка |
| `POST /api/chat`, правка/удаление/ссылка | устарел: демо-заглушка по словам «добавь»/«измени»; «удали» и ссылка дают «Демо-режим», `patch` пустой |
| `POST /api/chat`, `page_version` не совпала | работает, 409 |
| `POST /api/chat`, контекст всей страницы | нужен новый: контекст только `widget`/`link`, иначе 404 |

Расхождения для бэкенда (#26): поле `scenario {kind, reason}` в ответе чата (виды: question, extend, perspective, edit, remove, link, proposal); контекст `page`; распознавание удаления, ссылки и правки вывода вместо подстрок; эндпоинт отката по версии; пометка `source: human` у правленых блоков; пересборка профиля в обход кэша.

## Структура

| Папка | Что внутри |
|---|---|
| `src/api` | клиент, типы контракта |
| `src/lib` | кэш, применение патчей, фокус |
| `src/components` | `layout` (шапка, форма профиля), `views`, `widgets`, `graph` (стрелки), `modals` |
| `src/styles` | стили по областям |

## Запуск

```bash
cd frontend
npm install
npm run dev     # http://localhost:5173, /api проксируется на 127.0.0.1:8000 (бэкенд)
npm test        # vitest
npm run build   # проверка типов и сборка в dist/
```

В Docker сборку отдаёт nginx на `http://127.0.0.1:3000`, запросы `/api/*` он пересылает бэкенду ([docker.md](docker.md)).
