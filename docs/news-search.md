# 3. Сбор новостей (Python-класс `NewsSearch` + сервис `news_search`)

Класс `NewsSearch` превращает (компания, сфера, регион) в список лучших новостей из корпуса Postgres. Внутри: запросы к Postgres, эмбеддеры, HyDE, дедупликация, диверсификация. Код: [news_search/](../news_search/). Сервис `news_search` — тонкая HTTP-обёртка над классом (`POST /search`).

## Методы

Метод выбирается параметром вызова; бэкенд берёт его из конфига `NEWS_SEARCH_METHOD` ([backend.md](backend.md)).

| Метод | Откуда | Суть |
|---|---|---|
| `dense_xquad` (по умолчанию) | версия v2 | bge-m3 по всему корпусу, вопросы-потребности и HyDE, диверсификация xQuAD по блокам запросов, связки новостей |
| `dense_llm` | версия v1 | выбор кандидатов по основам слов, два эмбеддера (e5-large-instruct и bge-m3), LLM выбирает 30, слияние рангов |
| `lexical` | базовая линия | только совпадение основ слов с запросами, дедуп, ранг по числу совпавших запросов и свежести |

## Что делает `dense_xquad`, шаг за шагом

1. **Запросы.** Агент `queries` (для обезличенной компании из данных банка — `queries_anonymised`, выбор по флагу `anonymised`) пишет ключевые запросы по 11 блокам (конкуренты, регулирование, макро и т. д.); блоки потом служат «аспектами» для разнообразия выдачи. Агент `needs` пишет около 20 вопросов-потребностей руководителя, агент `hyde` — 40 правдоподобных заголовков полезных новостей. Эти ответы и готовые результаты поиска кэшируются в таблице `search_cache` (ключ запуска из компании, сферы и региона, имя шага, `jsonb`, время записи; таблицу создаёт и ведёт `news_search`). Результат поиска живёт сутки, результат допоиска час, ответы `queries`/`needs`/`hyde` без срока.
2. **Векторы статей.** Каждая статья корпуса за 365 дней один раз превращается в вектор bge-m3 по тексту «заголовок + первые 300 знаков». Векторы лежат в `vectors_bgem3.npz` по id статьи; при следующем запуске считаются только новые статьи.
3. **Поиск.** Для каждой потребности и каждого HyDE-заголовка считается сходство со всеми статьями, нормируется по корпусу (z-оценка), берётся среднее трёх лучших совпадений; потребности и HyDE складываются и умножаются на свежесть (≤30 дней ×1, ≤90 ×0,85, ≤365 ×0,6, старше ×0,3). Берутся 100 лучших.
4. **Второй источник.** К ним добавляются новости, найденные совпадением основ слов с ключевыми запросами (всего до 150 кандидатов): он находит то, что плотный поиск пропускает.
5. **Дедупликация и фильтр.** Дубли склеиваются (одинаковая ссылка, заголовок, Jaccard ≥ 0,6, TF-IDF по 4-граммам ≥ 0,55). Новости о самой компании убираются (для обезличенной компании из данных банка фильтра по названию нет).
6. **Диверсификация xQuAD.** Из кандидатов жадно набираются 30 новостей: каждая следующая выбирается за релевантность и за то, что покрывает блок запросов, ещё не покрытый выбранными.
   **Регион по размеру компании.** Если бэкенд передал `locality` (0–1: 1 — маленькая местная компания, 0 — крупная; считается из выручки и штата по данным банка, для компании, введённой по названию, — 0,1), новость не про регион профиля получает при отборе постоянную прибавку `NEWS_SEARCH_NONLOCAL_WEIGHT × (1 − locality)` к оценке (релевантность здесь нормирована в 0–1). Крупная компания охотнее меняет немного релевантности на федеральные новости, маленькая почти не меняет выдачу; фиксированного числа новостей нет. Регион новости определяется без LLM: регионы, названные в заголовке и первых 300 знаках (основы слов: «в Новосибирске», «Казанский»; название региона — в любом регистре, город — только с заглавной буквы внутри предложения, иначе «выборы» совпали бы с Выборгом), а если места не названы — регион издания из `collector/sources.json`. Точность 0,61, полнота 0,87 на 300 размеченных новостях; ошибки — в основном федеральные новости, перепечатанные региональным изданием ([benchmarks/region-boost.md](../news_search/benchmarks/region-boost.md)). Словарь `news_search/regions.json` собирает `regions_build.py` из 82 регионов словаря тегов, `sources.json` и городов из данных банка.
7. **Связки.** Среди 30 новостей ищутся пары «одна тема с разных сторон» (косинус 0,6–0,8: связаны, но не дубли), в аналитику идут 20 лучших пар.
8. Результат сохраняется на сутки; повторный запрос тех же параметров возвращается из файла.

`dense_llm` — те же шаги 1 (без needs), 5 и: кандидаты по основам слов (до 30 на запрос) → оценка заголовков обоими эмбеддерами по запросам и HyDE (лучшие 50 каждого, поочерёдно до 200) → агент `pick` (GLM) выбирает 30 → слияние рангов (RRF, k=10) с небольшим бонусом за подтверждение несколькими изданиями и умножением на свежесть.
`lexical` — шаги 1 (запросы), основы слов, 5; ранг: число совпавших запросов (+0,01 за каждое подтверждающее издание, до 3) × свежесть.

## Результат

```json
{"company": "…", "line": "…", "region": "…", "method": "dense_xquad", "date": "2026-10-24", "cost": 0.4,
 "top": [{"id": 0, "aid": 123456, "title": "…", "link": "https://…", "date": "…", "summary": "первые 300 знаков",
          "outlets": ["РБК"], "methods": ["D"], "blocks": {"government": 1}, "queries": [], "score": 0.91}],
 "pairs": [[0, 5]], "blocks": ["competitors_direct", "…"], "stats": {"candidates": 150, "unique": 120, "own_removed": 3}}
```

`aid` — номер статьи в таблице `articles`: по нему любую новость можно найти в корпусе (трассировка до источника).

## Допоиск (`refine`, только `dense_xquad`)

Добавляет новости к уже показанной странице, не пересобирая поиск. Нужен для обратной связи пользователя (#24, #27). Работает только с методом `dense_xquad`; для `lexical` и `dense_llm` сервис отвечает 422 — это сознательное отступление от «метод выбирается конфигом».

Виды (`kind`):
- `topic` — новая тема;
- `perspective` — та же тема с другой стороны: новые регион и направление бизнеса передаются в `region` и `line`, а регион и направление страницы — в `page_region` и `page_line` (по ним находится сохранённый запуск страницы);
- `claim` — отредактированный пользователем вывод: ищутся новости по его тексту (подкрепляющие и опровергающие; разметки «за/против» нет);
- `link` — новость, которую вставил пользователь: backend передаёт её заголовок и текст. Скачивание по ссылке и запись в корпус здесь не делаются.

Что делает, шаг за шагом:
1. Текст запроса превращается в вектор bge-m3. Для `perspective` векторов три: тема, «тема. регион», «тема. направление». Новых вызовов LLM нет; блоки ключевых запросов берутся из уже сохранённого запуска страницы (если его нет — один вызов `queries`).
2. Каждой статье корпуса считается сходство с запросами (z-оценка, среднее по запросам), умноженное на свежесть.
3. Новости, у которых косинус с любой удалённой пользователем новостью ≥ 0,7, получают половину оценки (порог и множитель предварительные, подбираются на бенчмарке).
4. Показанные и удалённые новости выбрасываются, берутся 150 лучших.
5. Кандидаты проходят дедупликацию вместе с показанными и удалёнными. Дублем считается та же ссылка, тот же или близкий заголовок, а также пересказ — косинус векторов ≥ 0,8 (порог подобран по нескольким темам: пересказы 0,80–0,85, разные новости одной темы до 0,73). Дубли и пересказы уже виденных новостей выбрасываются, из пересказов друг друга остаётся лучший по оценке. Затем фильтр новостей о самой компании. Склейка пересказов есть только в допоиске, в `/search` её нет.
6. Для `perspective` до 3 мест из `limit` отдаются новостям, где в заголовке или аннотации назван новый регион (по основам слов названия, без «область», «край», «республика») и косинус с темой не ниже 0,42. Лучшие по косинусу идут первыми и помечены `"regional": true`; если таких нет, места достаются остальным. Порог подобран глазами по 6 темам; столица региона и региональные издания пока не учитываются.
7. xQuAD набирает оставшиеся места (всего `limit`, по умолчанию 10) по блокам запросов профиля; ищутся связки.
8. Результат хранится час; если новостей меньше `limit`, отдаётся сколько есть (без 422).

```bash
curl -s -X POST localhost:8002/refine -H 'Content-Type: application/json' -d '{"company":"Делимобиль","line":"Глава найма","kind":"topic","text":"рынок такси в Казани","exclude_aids":[123],"removed_aids":[456],"limit":10}'
curl -s -X POST localhost:8002/refine -H 'Content-Type: application/json' -d '{"company":"Делимобиль","line":"Глава найма","page_line":"Глава найма","region":"Санкт-Петербург","page_region":"Москва","kind":"perspective","text":"электросамокаты","exclude_aids":[123]}'
```

Ответ — как у `/search` (`top`, `pairs`, `blocks`, `stats`, `cost`) плюс `kind` и `text`; в `stats` есть `excluded`, `removed`, `duplicates` (выброшенные дубли и пересказы), `regional` (сколько мест отдано региону); у каждой новости — флаг `regional`. Замеры: [benchmarks/refine.md](../news_search/benchmarks/refine.md).

## Как пользоваться

```python
from agents.client import Agents
from news_search import NewsSearch, postgres_corpus
from news_search.cache import PgCache  # без cache= результаты хранятся только в памяти процесса
search = NewsSearch(postgres_corpus(DATABASE_URL), Agents(), "/data", cache=PgCache(DATABASE_URL))
result = search.search("Делимобиль", "Глава найма", region="Москва", method="dense_xquad")
```

Через HTTP:

```bash
curl -s localhost:8002/methods
curl -s -X POST localhost:8002/search -H 'Content-Type: application/json' -d '{"company":"Делимобиль","line":"Глава найма","method":"lexical"}'
```

Если уникальных новостей меньше 30, сервис отвечает 422 «too few news collected».

## Настройки и проверка

`DATABASE_URL`, `AGENTS_URL`, `NEWS_SEARCH_NONLOCAL_WEIGHT` (вес федеральных новостей для крупных компаний, по умолчанию 0,5, 0 — выключено; после смены значения старые результаты в `search_cache` живут до суток), `NEWS_SEARCH_DATA` (папка кэша векторов статей, в compose — том `search_data`), `HF_HOME` (модели, том `hf_cache`). Первый поиск скачивает модели: bge-m3 (около 2,3 ГБ) и для `dense_llm` ещё e5-large-instruct. На CPU первый расчёт векторов по всему корпусу долгий (порядка 45 минут на 110 тыс. статей), на GPU — минуты. Замер на MacBook (arm64) по 512 случайным статьям: CPU 14,7 статей/с, MPS fp32 126,5, MPS fp16 172,5 (корпус из 75 тыс. статей примерно за 7 минут вместо 85); векторы fp16 и CPU совпадают с косинусом не ниже 0,9997. Запуск на GPU: `docker/up.sh`, см. docs/docker.md.

```bash
TEST_DATABASE_URL='postgres://news_test:news_test@127.0.0.1:55432/news_test?sslmode=disable' uv run pytest news_search
```

Тесты используют поддельный корпус, эмбеддер и агентов; живые модели в них не участвуют.

## Ограничения

- Одновременно выполняется один поиск (эмбеддеры занимают много памяти).
- Метод `lexical` — базовая линия, собранная из шагов остальных методов; он не повторяет отдельную старую версию.
- Фильтр «своих» новостей для компании вне словаря `ALIASES` грубый: основы слов названия должны все встретиться в заголовке.
- Даты в лентах берутся как есть; в части лент бывают анонсы с датой в будущем.
