# 3. Сбор новостей (Python-класс `NewsSearch` + сервис `news_search`)

Класс `NewsSearch` превращает (компания, сфера, регион) в список лучших новостей из корпуса Postgres. Внутри: запросы к Postgres, эмбеддеры, HyDE, дедупликация, диверсификация. Код: [news_search/](../news_search/). Сервис `news_search` — тонкая HTTP-обёртка над классом (`POST /search`).

## Методы

Метод выбирается параметром вызова; бэкенд берёт его из конфига `NEWS_SEARCH_METHOD` ([backend.md](backend.md)).

| Метод | Откуда | Суть |
|---|---|---|
| `dense_xquad` (по умолчанию) | версия v2 | bge-m3 по всему корпусу, вопросы-потребности и HyDE, диверсификация xQuAD по блокам запросов, связки новостей |
| `dense_llm` | версия v1 | выбор кандидатов по основам слов, два эмбеддера (e5-large-instruct и bge-m3), LLM выбирает 30, слияние рангов |
| `lexical` | базовая линия | только совпадение основ слов с запросами, дедуп, ранг по числу совпавших запросов и свежести |

## Что делает `dense_xquad`, шаг за шагом

1. **Запросы.** Агент `queries` пишет ключевые запросы по 11 блокам (конкуренты, регулирование, макро и т. д.); блоки потом служат «аспектами» для разнообразия выдачи. Агент `needs` пишет около 20 вопросов-потребностей руководителя, агент `hyde` — 40 правдоподобных заголовков полезных новостей. Результаты кэшируются в папке запуска.
2. **Векторы статей.** Каждая статья корпуса за 365 дней один раз превращается в вектор bge-m3 по тексту «заголовок + первые 300 знаков». Векторы лежат в `vectors_bgem3.npz` по id статьи; при следующем запуске считаются только новые статьи.
3. **Поиск.** Для каждой потребности и каждого HyDE-заголовка считается сходство со всеми статьями, нормируется по корпусу (z-оценка), берётся среднее трёх лучших совпадений; потребности и HyDE складываются и умножаются на свежесть (≤30 дней ×1, ≤90 ×0,85, ≤365 ×0,6, старше ×0,3). Берутся 100 лучших.
4. **Второй источник.** К ним добавляются новости, найденные совпадением основ слов с ключевыми запросами (всего до 150 кандидатов): он находит то, что плотный поиск пропускает.
5. **Дедупликация и фильтр.** Дубли склеиваются (одинаковая ссылка, заголовок, Jaccard ≥ 0,6, TF-IDF по 4-граммам ≥ 0,55). Новости о самой компании убираются (для обезличенной компании из данных банка фильтра по названию нет).
6. **Диверсификация xQuAD.** Из кандидатов жадно набираются 30 новостей: каждая следующая выбирается за релевантность и за то, что покрывает блок запросов, ещё не покрытый выбранными.
7. **Связки.** Среди 30 новостей ищутся пары «одна тема с разных сторон» (косинус 0,6–0,8: связаны, но не дубли), в аналитику идут 20 лучших пар.
8. Результат сохраняется на сутки; повторный запрос тех же параметров возвращается из файла.

`dense_llm` — те же шаги 1 (без needs), 5 и: кандидаты по основам слов (до 30 на запрос) → оценка заголовков обоими эмбеддерами по запросам и HyDE (лучшие 50 каждого, поочерёдно до 200) → агент `pick` (GLM) выбирает 30 → слияние рангов (RRF, k=10) с небольшим бонусом за подтверждение несколькими изданиями и умножением на свежесть.
`lexical` — шаги 1 (запросы), основы слов, 5; ранг: число совпавших запросов (+0,01 за каждое подтверждающее издание, до 3) × свежесть.

## Результат

```json
{"company": "…", "line": "…", "region": "…", "method": "dense_xquad", "date": "2026-10-24", "cost": 0.4,
 "top": [{"id": 0, "aid": 123456, "title": "…", "link": "https://…", "date": "…", "summary": "первые 300 знаков",
          "outlets": ["РБК"], "methods": ["D"], "blocks": {"government": 1}, "queries": [], "score": 0.91}],
 "pairs": [[0, 5]], "blocks": ["competitors_direct", "…"], "stats": {"candidates": 150, "unique": 120, "own_removed": 3}}
```

`aid` — номер статьи в таблице `articles`: по нему любую новость можно найти в корпусе (трассировка до источника).

## Как пользоваться

```python
from agents.client import Agents
from news_search import NewsSearch, postgres_corpus
search = NewsSearch(postgres_corpus(DATABASE_URL), Agents(), "/data")
result = search.search("Делимобиль", "Глава найма", region="Москва", method="dense_xquad")
```

Через HTTP:

```bash
curl -s localhost:8002/methods
curl -s -X POST localhost:8002/search -H 'Content-Type: application/json' -d '{"company":"Делимобиль","line":"Глава найма","method":"lexical"}'
```

Если уникальных новостей меньше 30, сервис отвечает 422 «too few news collected».

## Настройки и проверка

`DATABASE_URL`, `AGENTS_URL`, `NEWS_SEARCH_DATA` (папка кэшей, в compose — том `search_data`), `HF_HOME` (модели, том `hf_cache`). Первый поиск скачивает модели: bge-m3 (около 2,3 ГБ) и для `dense_llm` ещё e5-large-instruct. На CPU первый расчёт векторов по всему корпусу долгий (порядка 45 минут на 110 тыс. статей), на GPU — минуты.

```bash
TEST_DATABASE_URL='postgres://news_test:news_test@127.0.0.1:55432/news_test?sslmode=disable' uv run pytest news_search
```

Тесты используют поддельный корпус, эмбеддер и агентов; живые модели в них не участвуют.

## Ограничения

- Одновременно выполняется один поиск (эмбеддеры занимают много памяти).
- Метод `lexical` — базовая линия, собранная из шагов остальных методов; он не повторяет отдельную старую версию.
- Фильтр «своих» новостей для компании вне словаря `ALIASES` грубый: основы слов названия должны все встретиться в заголовке.
- Даты в лентах берутся как есть; в части лент бывают анонсы с датой в будущем.
