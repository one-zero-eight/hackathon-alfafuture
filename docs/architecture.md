# Архитектура

Система собирает новости, подбирает их под бизнес пользователя и объясняет, что они значат: выводы, риски, решения, с трассировкой до источников. Проект разделён на семь частей; каждая описана отдельным файлом.

```
RSS + Google News ──► collector (Go) ──► Postgres ◄── news_search (Python-класс + HTTP)
                          │ теги Gemma                       │ запросы, HyDE, пары: agents
                          ▼                                  ▼
                    словарь тегов            frontend ◄──► backend (FastAPI) ──► analytics ──► agents ──► LLM
                                                  профили, страницы, очередь        цепочка новость→вывод→решение
```

## Правила

- **Все обращения к LLM из Python идут через `agents`.** Исключение — Go-тегирование и геотеги в `collector`: у него свой клиент той же разрешённой модели (Gemma).
- Разрешены только модели из списка организаторов: Gemma 4 26B A4B, GLM-5.3-Flash, Qwen3.6 35B A3B, DeepSeek-V4.1-Flash, Qwen3-VL-30B-A3B-Instruct, Kimi-K2.6. Бюджет — 500 ₽ в сутки.
- Postgres общий. Таблицы корпуса принадлежит `collector` (остальные только читают), таблицу `profiles` ведёт `backend`, таблицу `search_cache` (шаги и результаты поиска) — `news_search`.
- Сервисы общаются по HTTP/JSON; контракты описаны в файлах разделов. Выбор метода поиска новостей — настройка бэкенда `NEWS_SEARCH_METHOD`.
- Трассировка: страница хранит ссылку на оригинал каждой новости, цитату-доказательство каждого вывода (проверена кодом на дословность) и страницу PDF для позиции банка; `aid` новости указывает на строку корпуса.

## Что происходит, когда пользователь вводит компанию и роль

1. Фронт отправляет профиль бэкенду, тот ставит его в очередь.
2. Бэкенд собирает карточку компании (при `company_id` — из данных банка) и просит `news_search` найти новости выбранным методом.
3. `news_search` просит `agents` написать запросы, потребности и HyDE-заголовки, ищет по корпусу, склеивает дубли, выбирает 30 разнообразных новостей и связки.
4. Бэкенд отдаёт новости `analytics`; та строит цепочки «новость → вывод → решение» (через `agents`) и проверяет их.
5. Бэкенд сохраняет страницу; фронт показывает её и подгружает детали по кликам.
6. Параллельно и независимо `collector` каждые 15 минут пополняет корпус и ставит теги.
