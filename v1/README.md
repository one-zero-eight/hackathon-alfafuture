# v1 — сборка дайджеста новостей одним циклом

Один скрипт: `(компания, сфера) → запросы → новости → дедуп → ранжирование эмбеддингами → топ-30`.

## Запуск

```bash
cd v1
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # torch подтянется сам
.venv/bin/python pipeline.py "Делимобиль" "Глава найма"
```

Нужен `.env` в корне репозитория или в `v1/` с `LLM_API_KEY`, `LLM_BASE_URL` (и опционально `LLM_BASE_URL_BACKUP`).
Результат: `out/<компания>__<сфера>/` — `queries.json`, `corpus.json`, `hyde.json`, `result.json`, `digest.md`.
Каждый шаг кэшируется в этой папке; чтобы пересчитать шаг, удали его файл. Ответы Google News кэшируются в `cache/gn.json`.

## Как это работает

1. **Запросы.** DeepSeek-V4.1-Flash по `prompt.md` пишет поисковые запросы по блокам (конкуренты, регулирование, рынок труда и т.д.).
2. **Сбор.** A — Google News RSS по каждому запросу (до 15 новостей). B — 50 RSS-лент изданий (`outlets50.json`), новости подбираются к запросам по пересечению основ слов.
3. **Дедуп и фильтр.** Дубли склеиваются (url, точный заголовок, Jaccard, TF-IDF по 4-граммам). Новости о самой компании убираются.
4. **Эмбеддинги.** multilingual-e5-large-instruct и bge-m3 считают близость заголовков к запросам и к 40 «гипотетическим заголовкам» (HyDE, пишет DeepSeek). Оценка умножается на свежесть (≤30 дней ×1, ≤90 ×0,85, ≤365 ×0,6, старше ×0,3). От каждой модели берётся топ-50.
5. **Выбор LLM.** Объединённые кандидаты (до 200) отдаются GLM, Qwen и DeepSeek, каждая выбирает 30.
6. **Слияние.** RRF (k=10) по трём спискам, бонус за подтверждение несколькими изданиями и каналами, умножение на свежесть → итоговый топ-30.

Ограничения: у компании вне словаря `ALIASES` в `pipeline.py` фильтр «своих» новостей грубый (основы слов названия в заголовке); даты в лентах берутся как есть.
