# v1 — сборка дайджеста новостей одним циклом

Цикл: `(компания, сфера) → запросы → поиск по корпусу новостей в PostgreSQL → дедуп → ранжирование эмбеддингами → топ-30`.
Корпус наполняется отдельно от поиска (`ingest.py` и Go-сборщик `backend/`).

## Корпус новостей

`backend/` и `compose.yaml` — копия сервиса Александра (ветка `tags`) без тегирования: LLM и worker отключены, статья с текстом сразу получает статус `completed`, окно приёма новых источников — 365 дней. Go-сборщик опрашивает РБК, «Коммерсантъ» и ЦБ.

```bash
cd v1 && cp .env.example .env            # задай POSTGRES_PASSWORD (и тот же пароль в DATABASE_URL)
docker compose up -d --build              # Postgres на 127.0.0.1:5433, API на :8080
.venv/bin/python ingest.py feeds --every 900     # 47 RSS-лент из outlets50.json, раз в 15 минут
.venv/bin/python ingest.py gn --days 180         # бэкфилл Google News: каждая тема × недельные окна after:/before:
```

`ingest.py gn` берёт темы из `cache/gn.json` и `out/*/queries.json`, помнит сделанные пары в `cache/gn_done.json` и продолжает с места остановки. Дубли отсекает уникальный ключ `(source_id, dedup_key)`, поэтому повторные запуски безопасны. Для каждого издания Google News создаётся свой `source` (в `articles` нет колонки издания).


```bash
cd v1
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # torch подтянется сам
.venv/bin/python pipeline.py "Делимобиль" "Глава найма"
```

Нужен `.env` в корне репозитория или в `v1/` с `LLM_API_KEY`, `LLM_BASE_URL` (и опционально `LLM_BASE_URL_BACKUP`).
Результат: `out/<компания>__<сфера>/` — `queries.json`, `corpus.json`, `hyde.json`, `result.json`, `digest.md`.
Каждый шаг кэшируется в этой папке; чтобы пересчитать шаг, удали его файл. Ответы Google News кэшируются в `cache/gn.json`.

## Как это работает

1. **Запросы.** DeepSeek-V4.1-Flash по `prompt.md` пишет поисковые запросы по блокам (конкуренты, регулирование, рынок труда и т.д.).
2. **Поиск по корпусу.** Из PostgreSQL берутся новости за последние 365 дней (`CORPUS_DAYS`), к каждому запросу подбирается до 30 (`PER_QUERY_CORPUS`) по пересечению основ слов. Живые RSS и Google News при поиске не вызываются.
3. **Дедуп и фильтр.** Дубли склеиваются (url, точный заголовок, Jaccard, TF-IDF по 4-граммам). Новости о самой компании убираются.
4. **Эмбеддинги.** multilingual-e5-large-instruct и bge-m3 считают близость заголовков к запросам и к 40 «гипотетическим заголовкам» (HyDE, пишет DeepSeek). Оценка умножается на свежесть (≤30 дней ×1, ≤90 ×0,85, ≤365 ×0,6, старше ×0,3). От каждой модели берётся топ-50.
5. **Выбор LLM.** Объединённые кандидаты (до 200) отдаются GLM, Qwen и DeepSeek, каждая выбирает 30.
6. **Слияние.** RRF (k=10) по трём спискам, бонус за подтверждение несколькими изданиями и каналами, умножение на свежесть → итоговый топ-30.

Ограничения: поиск по корпусу пока лексический (без эмбеддингов по всей базе); в `ancb` бывают анонсы с датой в будущем; часть лент (forbes, izvestia, cnews и др.) отдаёт 0 записей;  у компании вне словаря `ALIASES` в `pipeline.py` фильтр «своих» новостей грубый (основы слов названия в заголовке); даты в лентах берутся как есть.
