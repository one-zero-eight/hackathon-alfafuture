# SETUP — запуск всей системы v1 одной командой

Шесть контейнеров в `compose.yaml`:

| Сервис | Что делает | Порт на хосте |
|---|---|---|
| `postgres` | БД новостей (таблицы `sources`, `articles` из сервиса Александра) | `127.0.0.1:5433` |
| `collector` | Go-сервис Александра (тегирование выключено): опрашивает РБК, «Коммерсантъ», ЦБ, отдаёт свой API | `127.0.0.1:8080` |
| `scraper` | `ingest.py loop`: просыпается и пополняет БД из 129 RSS-лент и Google News | — |
| `pipeline` | воркер: берёт профиль (компания + роль) из очереди в БД, запускает `pipeline.py` (поиск по корпусу, эмбеддинги, три LLM) и `analyze.py` (LLM пишет аналитику, решения, риски, связи) | — |
| `api` | сервер для фронта: контракт `docs/ENDPOINTS.md`; без профиля мок-страница + свежие новости, с профилем страница из БД | только внутри Docker |
| `web` | собранный фронт (Vite) за nginx, `/api` проксируется на `api` | `http://127.0.0.1:3000` |

## Что нужно

- Docker с Compose v2 (проверено на 28.1.1).
- Свободные порты 3000, 5433, 8080.
- Ключи LLM в корневом `.env` репозитория (`LLM_API_KEY`, `LLM_BASE_URL`): их читает контейнер `pipeline`. Без них профили будут падать со статусом `failed`.
- Место под модели: первый прогон скачивает в том `hf_cache` две эмбеддинг-модели (`intfloat/multilingual-e5-large-instruct`, `BAAI/bge-m3`), около 4,5 ГБ.

## Запуск

```bash
cd v1
cp .env.example .env
# в .env замените change-me на свой пароль (латиница и цифры) в обеих строках: POSTGRES_PASSWORD и DATABASE_URL
docker compose up -d --build
docker compose ps          # все пять сервисов Up, postgres и collector healthy
```

Первая сборка занимает несколько минут (Go, npm, образы). Откройте `http://127.0.0.1:3000`.

## Проверка

```bash
curl -s localhost:3000/api/page | python3 -m json.tool | head -30   # виджеты; id вида db<номер> — новости из БД
curl -s localhost:8080/v1/status                                     # collector: сколько статей в БД
docker compose exec postgres psql -U news -d news -c "select count(*) from articles"
docker compose logs -f scraper                                       # что принёс последний проход
```

## Как это работает

1. `collector` при старте создаёт таблицы и каждые 10 минут опрашивает РБК, «Коммерсантъ», ЦБ. Статья с текстом сразу получает статус `completed`.
2. `scraper` в цикле: каждые 15 минут читает RSS-ленты из `outlets50.json` и `outlets_new.json`; каждые 6 часов делает скользящий трёхдневный проход Google News (по изданиям `site:<host>` и по темам из `topics_extra.txt` и `cache/gn.json`). Дубли отсекает уникальный ключ `(source_id, dedup_key)`.
3. **Профиль.** В шапке фронта два поля: компания и роль. Кнопка «Подобрать» шлёт `POST /api/profile`; `api` кладёт заявку в таблицу `v1_profiles`, фронт опрашивает `GET /api/profile/{key}` раз в 3 секунды.
4. **Воркер `pipeline`** берёт заявку и делает: (а) LLM пишет поисковые запросы и «гипотетические заголовки»; (б) новости за 365 дней ищутся в корпусе по основам слов; (в) дедуп; (г) два эмбеддера и три LLM выбирают топ-30; (д) `analyze.py`: одна LLM по топ-30 пишет 8 новостей-карточек, 4–5 выводов, 3–4 решения с рисками и связи. Заголовок, ссылка, издание и дата новостей берутся из корпуса, не от LLM. Результат-страница сохраняется в `v1_profiles.page`.
5. **Кэш.** Одна и та же пара (компания, роль) в течение 24 часов отдаётся из БД мгновенно и бесплатно. Внутри воркера кэшируются запросы и «гипотетические заголовки» (том `pipeline_out`), снимок корпуса и итог топ-30 живут 24 часа, модели лежат в `hf_cache`.
6. **Без профиля** страница как раньше: демо про Газпром плюс 12 свежих новостей из БД по регулярному выражению (`NEWS_REGEX`).
7. `web` отдаёт собранный фронт; запросы `/api/*` nginx пересылает на `api`.

## Проверка профиля из консоли

```bash
curl -s -X POST localhost:3000/api/profile -H 'Content-Type: application/json' -d '{"company":"Делимобиль","role":"Глава найма"}'
curl -s localhost:3000/api/profile/<key>          # queued -> running -> ready
curl -s "localhost:3000/api/page?profile=<key>"
docker compose logs -f pipeline
python test_analyze.py                              # самопроверка разбора ответа LLM, без сети
```

## Первичное наполнение корпуса (по желанию)

Скраппер набирает данные постепенно. Чтобы сразу получить глубину за 2 месяца, запустите бэкфилл из контейнера:

```bash
docker compose run --rm scraper python -u ingest.py gnsite --days 60 --step 2   # по изданиям, ~1,5 тыс. запросов
docker compose run --rm scraper python -u ingest.py gn --days 60 --step 7        # по темам
```

Google News иногда отвечает 429; скрипт повторяет запросы и можно запускать его заново, он продолжит с места остановки (кэш внутри контейнера не сохраняется, поэтому после пересоздания контейнера пары запросов повторятся, это безопасно из-за дедупа).

## Остановка и сброс

```bash
docker compose down        # остановить, данные БД сохраняются в томе v1_postgres_data
docker compose down -v     # ВНИМАНИЕ: удалит том с корпусом новостей
```

## Известные ограничения

- Ранжирование и аналитика — временные: `pipeline.py` и `analyze.py` заменит код Льва. Чат по виджетам профиля отвечает заготовкой из карточки, патчи страницы (добавь/измени) работают как в моке.
- Первый запуск профиля занимает минут 10–12 на CPU (замер: «Делимобиль / Глава найма», 708 с без скачивания моделей) и стоит около 5 условных единиц LLM (4,88 по `usage.cost`; единица, по-видимому, рубль, это не подтверждено). Повтор в течение суток бесплатный.
- `okved` у профильной страницы всегда «не указан»: ОКВЭД не вводится.
- Ссылки новостей из Google News ведут через редирект `news.google.com`, а не на оригинал.
- РБК с некоторых сетей не открывается (ошибка TLS); у `collector` в таких случаях в логе `source poll failed`.
- Тесты Go-сервиса из копии Александра ожидают статус `pending` и не обновлены.
- Пароль БД лежит в локальном `.env` (он в `.gitignore`).
